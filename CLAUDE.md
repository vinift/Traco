# Traço Notas — contexto para o Claude Code

App de notas manuscritas estilo Notewise, feito para o **Xiaomi Pad 7** (caneta Focus Pen + dedo, tela ~2,5 de densidade, Android). É um **PWA** publicado no **GitHub Pages** a partir deste repositório (`vinift/Traco`, branch `main`) e instalado no tablet como **TWA** (gerado no PWABuilder). Backup e sincronização no **Google Drive** do usuário.

Este arquivo é o "caderno de bordo" do projeto: qualquer sessão nova, de qualquer conta, deve conseguir continuar o trabalho só lendo isto. **Ao terminar cada rodada, atualize o "Histórico" e o que mais tiver mudado aqui.**

---

## 1. Começando numa sessão nova

1. `git fetch origin main && git log --oneline -5 origin/main` — veja a versão atual (também em `js/app.js` → `version`). Trabalhe a partir da `main` mais recente.
2. Se o ambiente exigir um branch de trabalho da sessão (ex.: `claude/...`), commite nele **e** publique na `main` (`git push origin HEAD:main`) — ver autorização abaixo. Se a `main` andou na frente, faça `git fetch` + merge antes de publicar (nunca force-push).
3. Não crie pull requests (o Vinicius publica direto na `main`).
   Se o GitHub recusar o push, a conta da sessão precisa ter o GitHub conectado com acesso ao repositório `vinift/Traco` (o Vinicius conecta em claude.ai → Configurações → Conectores / app do Claude no GitHub).
4. Leia a seção 9 (Histórico) para saber o que já foi feito e por quê — várias decisões foram ida-e-volta (zoom, memória, trava de rolagem) e não devem ser desfeitas sem perguntar.

## 2. Como trabalhar com o Vinicius

- **Responda sempre em português (pt-BR).** Ele é destro, estuda (informática, redes…) e usa o app diariamente no Pad 7.
- **Autorização permanente:** pode publicar toda versão/patch **direto na `main`**, sem perguntar antes.
- Pergunte antes de decisões de produto/UX que tenham mais de um caminho razoável. A ferramenta de perguntas com opções (com uma "(Recomendado)") funciona bem com ele; ele às vezes responde com texto livre combinando opções.
- Cada rodada = **uma versão nova** (patch `0.24.1 → 0.24.2` para ajustes/correções; minor `0.24 → 0.25` para recursos novos), registrada no `LEIA-ME.md`.
- Relatório no fim de cada rodada: o que mudou (em linguagem de usuário), como foi testado (com números quando houver), limitações honestas (o que não dá para testar sem o tablet) e onde ajustar. Sugestões de melhoria no fim são bem-vindas mas curtas — ele costuma recusar a maioria e prefere pedir o que quer.
- Ele testa no tablet e volta com feedback curto (às vezes com print). Quando algo "ficou pior", ele prefere **voltar ao comportamento anterior com um ajuste** do que uma regra totalmente nova.
- Ele **não quer** suíte de testes automatizados no repositório (testes ficam em scripts avulsos no scratchpad).
- Use `vinift` em URLs de exemplo (github.com/vinift, vinift.github.io/Traco).
- Nunca apague arquivos que só existem no repositório (ex.: `.well-known/assetlinks.json` do TWA, se existir). Exceção: lixo comprovadamente seu (ex.: prints de teste commitados por engano — já aconteceu na v0.19.1 e foi limpo na v0.23.1).

## 3. Lançar uma versão (checklist)

1. Trocar a versão em **três** lugares: `js/app.js` (`version: 'x.y.z'`), `sw.js` (`const VERSION = 'traco-vx.y.z'`) e **todos** os `?v=x.y.z` do `index.html` (cache busting). Conferir com `grep -c "versão-antiga" index.html js/app.js sw.js` → tudo 0.
2. Arquivo JS novo → incluir no `index.html` (na ordem certa) **e** na lista `FILES` do `sw.js`.
3. `for f in js/*.js sw.js; do node --check $f; done`.
4. Seção `## Novidades da vX.Y.Z` no topo das novidades do `LEIA-ME.md` (acima da anterior), escrita para o usuário.
5. Linha nova no Histórico (seção 9) deste arquivo, escrita para o próximo desenvolvedor (nomes de funções/variáveis).
6. Commit com a versão no título (ex.: `v0.24.2: trava de rolagem vertical a partir de 70% de zoom`), push no branch da sessão e na `main`.
7. No tablet, o usuário toca em "Verificar atualização" (v0.43.1: pílula no topo da tela inicial, ou no ⋯ da nota).

## 3b. Gerar o APK de novo (PWABuilder) — quando muda algo do manifesto

**APK regerado em 21/11/2026 (deu certo):** PWABuilder → Package For Stores → Android (Google Play) → All Settings: Host `vinift.github.io`, Start URL `/Traco/`, Version `1.2.0.0`, **Version code 3** (próxima vez: 4+), Display mode **Fullscreen sticky**, Signing key **Use mine** com o `signing.keystore` + alias/senhas do `signing-key-info.txt` do zip "Google Play package" da 1ª geração (o usuário guarda no Drive), Fallback **Custom Tabs** (não usar Web View). NÃO usar "Download Test Package" (chave de teste → barra do Chrome). Conferir antes de instalar: `assetlinks.json` do zip novo com o MESMO `package_name` e `sha256_cert_fingerprints` do antigo. Na 1ª tentativa apareceu a barra do Chrome (X, nome do site, compartilhar, ⋮) = verificação do Digital Asset Links falhou (chave/pacote diferentes); refeito com a chave antiga → resolvido. Resultado: barra do sistema por cima funcionou; **"Abrir com" PDF NÃO apareceu** — o APK do PWABuilder não registra `file_handlers` (não insistir; o usuário aceitou). Caminho para PDFs de fora: "Compartilhar" (`share_target`).

"Verificar atualização" só atualiza a parte web. Recursos que o **Android** precisa conhecer vêm do `manifest.webmanifest` **no momento em que o APK é gerado**: "Abrir com" (`file_handlers`, v0.29), "Compartilhar para" (`share_target`, v0.29), nome, ícone, cor. Em 20/11/2026 o usuário relatou que o Traço não aparecia no "Abrir com" porque o APK era de antes da v0.29 — instruções dadas:
1. Backup no Drive antes (Configurações → Google Drive → sincronizar). Os dados do TWA ficam no armazenamento do Chrome para o site, mas por segurança.
2. pwabuilder.com → endereço `https://vinift.github.io/Traco/` → Package for stores → **Android** → *Options/All settings*.
3. **Mesmo Package ID** do APK atual (ex.: `io.github.vinift.twa` — confira no app instalado: Configurações do Android → Apps → Traço → detalhes) e **mesma chave de assinatura**: "Signing key → Use mine" com o `signing.keystore` + senhas do `signing-key-info.txt` do zip da primeira geração. Com chave nova o Android recusa instalar por cima (assinatura diferente) e o `assetlinks.json` (no repositório do site raiz `vinift.github.io`, em `/.well-known/`, não neste) teria de ser atualizado com a impressão digital nova — senão aparece a barra de endereço.
4. Gerar, baixar o zip, instalar o `.apk` por cima do atual (permitir "fontes desconhecidas" para o gerenciador de arquivos).
5. Testar: tocar num PDF no gerenciador de arquivos → "Abrir com" → Traço → deve abrir a página "Abrir PDF no Traço". Compartilhar um PDF → Traço também.
**Barra do sistema preta que empurra a tela (caminho novo, 20/11/2026):** o Bubblewrap aceita `display` = `standalone` | `fullscreen` | `fullscreen-sticky` ("fullscreen-sticky corresponds to Android's Immersive Sticky", README do bubblewrap/packages/cli). No modo imersivo fixo as barras aparecem POR CIMA (semitransparentes) ao puxar da borda e somem sozinhas, sem redimensionar — é o que o usuário quer. Instrução dada: no PWABuilder → Android → Options → **Display mode = Fullscreen sticky** ao gerar o APK novo. Se mesmo assim a tela pular, revisar `SafeArea`/`StableVH` (margens congeladas) para esse modo. Issue conhecido (bubblewrap #1035): área do entalhe em branco em fullscreen — o Pad 7 não tem entalhe.
Não confirmado (não deu para ler a doc do PWABuilder daqui): se há uma opção a marcar para file handlers / share target; o Bubblewrap (gerador por baixo) aceita `fileHandlers` e `shareTarget` no twa-manifest.json e "merge" leva os campos do manifesto web. Se depois de gerar o Traço ainda não aparecer, abrir o zip e conferir no `twa-manifest.json` se `fileHandlers` está lá.

## 4. Arquitetura (JS puro, sem build)

- Scripts clássicos que compartilham globais, carregados nesta ordem: util, store, geom, render, pdf, tpl-import, drive, editor, toolbar, tables, tiles, navigation, richtext, crop, shapeedit, colorpicker, fade, ui, ocr, beautify, import-notewise, library, plugins, workspace, split, timer, studyreport, pdfopen, notemenu, app (autotoc vem logo depois de workspace; calligraphy logo depois de beautify).
- `const Editor`, `const UI`, `const StudyTimer` etc. **não** ficam em `window`: use `typeof Editor !== 'undefined'`.
- Vários arquivos estendem o editor com `Object.assign(Editor, {...})` (tiles, navigation, richtext, tables, crop, colorpicker). **`Object.assign` não copia getters** (avalia uma vez) — use métodos (ex.: `previewCap()`, `tileCap()`).
- Comentários: prefira `/* */` em linhas longas — um `//` já engoliu código mais de uma vez. O código é denso (linhas longas); edite com substituições exatas e confira com `node --check`.
- `vendor/`: pdf.js (`pdf.min.mjs` + worker) e `pdf-lib.min.js`.
- Ícones: objeto de SVGs em `js/util.js` (`icon('nome')`, `iconEl`). Ícones já criados por nós: `timer`, `sparkle`, `nodes`, `lockSide`, `swapSides`.
- UI utilitária (`js/util.js`): `el(tag, attrs, ...filhos)`, `$`, `$$`, `toast(msg, ms)`, `openModal`, `confirmBox`, `openPop(âncora, conteúdo, {onClose})` / `closePop()`, `menu`, `clamp`, `clone`, `uid`, `debounce`.

## 5. Mapa de comportamentos (onde está cada coisa)

### Zoom, rolagem e memória (muita ida-e-volta — não mude sem perguntar)
- **`clampCam` (editor.js), horizontal — v0.26 estilo Notewise:** margens `barMargins()` = `{mL: borda direita do rail/subrail sobre esta tela + 8 (maior valor visto, para não pular ao trocar de ferramenta; `barsOver(rect)`), mR: 12}`, medidas de novo só em `resize`, `applyBarSize` (`resetMargins`) e ResizeObserver das barras. Folha mais larga que `W − mL − mR` → rola de lado até a borda encostar na margem (sem folga). Mais estreita → `hScrollable()` falso: rolagem só vertical (arrasto e inércia) e `left = max(mL, (W − pw)/2)` (encosta nas barras, depois centraliza aos poucos). Vale também na pinça. `fitWidth` encaixa entre as margens. **Substituiu** a trava por % (`lockZ`/`S.lockZoom`, `_xHold`, folga 0,35·vw + 60/z da v0.20–v0.25), que o usuário achou ruim. O lado passivo da tela dividida (`svPane.clamp`) usa as mesmas regras.
- Tela dividida e memória (v0.26): `tileCap()` cai para ~55% e `previewCap()` para 6 quando o editor ocupa só parte da tela; lado passivo `SV_BASE_W` 1100. Divisória em prévia (transform) e aplica ao soltar. `Editor.resize` só muda o tamanho das telas se mudou (mudar apaga a tela). `placeScroll` não roda a cada rolagem.
- **Trava vertical do arrasto (moveGesture):** trava se o dedo sai quase reto (|dx| ≤ 0,2·|dy|) e solta com 14 px para o lado.
- **Fim da nota:** `camMaxBase` deixa max(220 px, 30% da tela) abaixo da última página (v0.27; antes 90 px) antes de começar o puxar (o lado passivo também).
- **Puxar para adicionar página:** `PULL_MAX/PULL_ADD` 260/190 (~340 px de puxada) e só conta se o gesto começou já parado no fim (`g.atEnd`).
- **Blocos (tiles.js):** cada nível de zoom tem seus blocos; durante o gesto (`st.zooming`) não se renderiza nível novo, usa-se a reserva `_fbLvl` (sempre o último nível **completo**, `_curDone`) esticada. Miniatura da página (`pc.preview`, até 960 px) é o fundo de última instância; a velha fica na tela até a nova ficar pronta. Itens acrescentados no fim da página são pintados direto nos blocos e na miniatura (`paintOnTile`/`paintOnPreview`) em vez de redesenhar. `keepVisible` protege da remoção o que está na tela.
- **Qualidade ao tirar o zoom (`S.zoomQuality`, Configurações → Zoom):** "econômica" (padrão) = `tileCap()` 64 blocos (48 em aparelhos < 8 GB) e `previewCap()` 6 (v0.28; antes 90/60 e 10 — as barras sumiam em parte na pinça no Pad 7; medido: pico 165 → 150 MB, parado depois do zoom 159 → 131 MB, igual à v0.24.10 antes da redução) — **a "alta" (200 blocos, 18 miniaturas, camada afastada `_ovLvl` via `prefetchOverview`, miniaturas criadas durante o gesto) ficou pesada no Pad 7 e fazia as barras piscarem na pinça**. Sintoma de memória de desenho cheia no Android = barras piscando/sumindo.
- `updateHud` (texto do zoom na barra) é limitado a ~8×/s durante o gesto.

### Caneta e escrita
- Entrada da caneta por `pointerrawupdate` (`onRaw`, mais cedo que `pointermove`; `action.raw2` evita processar em dobro).
- Estabilização por ferramenta/tipo (`stabLevel`, `S.stabPen[tipo]`; v0.37.1: escala 0–`STAB_MAX` 20, padrão 10 em todas): filtro adaptativo em `addDrawPoint`; "corda" nos níveis 9–10 (0,45 px/nível) e, de 11 a 20 (`X = L − 10`), corda + 1,1·X px de tela, `kb` − 0,0145·X (0,25 → 0,105), divisor da velocidade + 14·X, e `smoothArc` do fim do traço com sigma × (1 + 0,12·X). Antes < 3,5 px sempre voltava ao lugar (o usuário escreve pequeno e precisa de ajustes de 1–3 px). Movimento < 14 px não gruda (`near0` em `moveSel`).

- Laço: forma é selecionada se algum ponto está dentro OU se o traço do laço cruza a linha dela (`elInLasso`).
- Com a caneta, mover/redimensionar/girar é sempre livre (`action.penFree`, mesmo efeito do `noSnap` do 2º dedo).
- Cores (v0.28): `UI.groupColors()` (caneta + marca-texto do grupo atual) aparecem primeiro em `colorPop` (aba Paleta), em `colorSection` (menos nas próprias ferramentas caneta/marca-texto) e na moldura (`framePop`, com botão de cor personalizada `.fr-more`); cor do modelo de página usa `colorPop` (`.tpl-color`) em vez de `input type=color`.

## 8. Formato do Notewise (descoberto por engenharia reversa)

`.notewise` = ZIP com `note`, `page/<id>`, `image/<id>`, `pdf/<id>`; `note` e `page` são protobuf em base64. Página 3480×4000 un. (300 dpi) → 1000 px de largura no Traço.
Elemento da página (campo 4): 3 = matriz, 4 = traço, 5 = marca-texto, 6 = forma, 7 = imagem, 8 = texto, 11 = tabela, 14 = comentário.
Imagem (campo 7): 1 = id, 2 = retângulo da imagem inteira {1:x1,2:y1,3:x2,4:y2}, **4 = recorte visível** (mesmo referencial), 7 = {1: cor, 2: largura} (provável moldura), 9 = int (0/8/25/30, provável raio do canto), 10 = opacidade, 6/8 = ints desconhecidos, 3 = bytes (raro, desconhecido).
Imagem no Traço: `{type:'image', x, y, w, h, blobId, rot?, crop?: {x,y,w,h}}` — `crop` em frações da imagem original; `x/y/w/h` é a caixa visível.
